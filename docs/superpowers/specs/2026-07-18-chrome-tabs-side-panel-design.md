# Chrome Tabs Side Panel 插件设计规格

- 日期：2026-07-18
- 状态：待用户审阅
- 技术方向：React + Vite + Chrome Extension Manifest V3

## 1. 背景与目标

当 Chrome 中打开大量标签页时，顶部标签栏会严重压缩，用户难以通过标题和图标快速找到目标标签页。

本插件在浏览器右侧的 Chrome Side Panel 中提供完整、可搜索、按窗口分组的标签页列表，使用户无需在拥挤的顶部标签栏中逐个寻找。

首版目标：

1. 搜索与筛选标签页。
2. 点击列表项切换到对应标签页和窗口。
3. 关闭标签页。
4. 按 Chrome 窗口分组展示。
5. 监听浏览器事件并实时同步列表。
6. 同时支持全局和单个标签页的隐私脱敏控制。

## 2. 范围

### 2.1 首版包含

- Chrome Manifest V3 扩展。
- Chrome Side Panel 页面。
- 工具栏扩展图标点击后打开 Side Panel。
- 查询普通 Chrome 窗口中的标签页。
- 按窗口分组、展开和折叠。
- 标题和 URL 搜索。
- “全部 / 当前窗口 / 活动标签”筛选。
- 点击标签页切换。
- 关闭标签页。
- 标签页和窗口状态实时同步。
- 全局脱敏切换。
- 单个标签页脱敏切换。
- 浅色与深色系统主题。
- 键盘操作和基础无障碍支持。

### 2.2 首版不包含

- 拖拽重新排序标签页。
- Chrome Tab Groups 的创建、编辑或分组展示。
- 标签页收藏、稍后阅读或会话恢复。
- 云端同步和用户账户。
- 标签页内容预览或截图。
- 历史记录搜索。
- 批量关闭标签页。
- 自定义持久化脱敏规则。

## 3. 技术方案

### 3.1 技术栈

- React
- TypeScript
- Vite
- Chrome Extension Manifest V3
- 原生 CSS，使用 CSS Custom Properties 管理主题 token
- Vitest + React Testing Library（单元和组件测试）

不引入大型 UI 组件库。图标使用项目内统一维护的 SVG React 组件，避免第三方运行时依赖和外部资源请求。

### 3.2 扩展组成

- `manifest.json`：声明 Side Panel、权限、后台 Service Worker 和工具栏 Action。
- `background` Service Worker：设置点击扩展工具栏图标时打开 Side Panel。
- `sidepanel.html`：Vite 页面入口。
- React Side Panel 应用：负责查询、展示和操作标签页。

### 3.3 Chrome 权限

计划使用：

- `sidePanel`：显示 Chrome Side Panel。
- `tabs`：读取标签页标题、URL、favicon 及执行激活、关闭操作。

扩展不需要主机权限，不读取网页 DOM，也不向远程服务器发送标签页信息。

## 4. 信息架构

Side Panel 从上至下分为：

1. **顶部栏**
   - 产品名称。
   - 当前标签页总数。
   - 全局脱敏按钮。

2. **搜索与筛选区**
   - 搜索输入框。
   - 全部标签。
   - 当前窗口。
   - 活动标签。

3. **窗口分组列表**
   - 当前窗口优先。
   - 其他窗口按 Chrome 返回顺序展示。
   - 分组头包含窗口名称、标签页数量和展开状态。
   - 分组内展示标签页行。

4. **反馈层**
   - 加载状态。
   - 搜索无结果状态。
   - 浏览器 API 错误及重试入口。
   - 关闭等操作失败的非阻塞提示。

## 5. 核心交互

### 5.1 搜索

- 输入后立即在内存中进行大小写不敏感匹配。
- 当标签页处于可见状态时，匹配标题和完整 URL。
- 当标签页处于脱敏状态时，仍允许使用真实标题和 URL 搜索，但搜索结果不得通过高亮片段或辅助文本泄漏内容。
- 清空按钮可一次清除搜索词。
- `Escape` 在搜索框内优先清空搜索词。

### 5.2 筛选

- **全部**：展示所有普通窗口及其匹配标签页。
- **当前窗口**：只展示当前聚焦窗口中的匹配标签页。
- **活动标签**：展示每个窗口当前激活的标签页。
- 搜索和筛选条件组合生效。
- 不包含 Chrome 内部无法被扩展管理的特殊页面时，按 `chrome.tabs.query` 的实际结果处理。

### 5.3 切换标签页

点击标签页主内容区域：

1. 调用 `chrome.tabs.update(tabId, { active: true })`。
2. 如果目标标签位于其他窗口，调用 `chrome.windows.update(windowId, { focused: true })`。
3. Chrome 事件回调触发状态同步；必要时主动刷新作为容错。

关闭按钮和脱敏按钮必须阻止事件冒泡，不能意外切换标签页。

### 5.4 关闭标签页

- 点击行尾关闭按钮调用 `chrome.tabs.remove(tabId)`。
- 成功后通过 `tabs.onRemoved` 实时更新。
- 失败时保留列表项并显示可恢复的错误提示。
- 首版不增加确认对话框，以减少高频操作成本。

### 5.5 窗口分组

- 当前聚焦窗口排列在最上方并标记“当前窗口”。
- 其他窗口使用“窗口 2”“窗口 3”等会话内名称。
- 每个组显示当前筛选后的结果数；无搜索或筛选时即为窗口总标签数。
- 分组支持展开和折叠。
- 折叠状态保留在当前 Side Panel React 会话中，不持久化。
- 如果筛选后某窗口没有结果，则不显示该窗口分组。

### 5.6 实时同步

监听以下事件并刷新或局部更新状态：

- `chrome.tabs.onCreated`
- `chrome.tabs.onUpdated`
- `chrome.tabs.onMoved`
- `chrome.tabs.onActivated`
- `chrome.tabs.onRemoved`
- `chrome.tabs.onAttached`
- `chrome.tabs.onDetached`
- `chrome.tabs.onReplaced`
- `chrome.windows.onCreated`
- `chrome.windows.onRemoved`
- `chrome.windows.onFocusChanged`

为避免短时间内连续事件引发过多查询，刷新函数进行轻量合并：同一事件循环或短间隔内只执行一次完整查询。组件卸载时移除全部监听器。

## 6. 脱敏设计

### 6.1 默认状态

每次打开新的 Side Panel 页面会话时，默认全局脱敏开启。状态不写入 `chrome.storage`，关闭并重新打开页面后恢复为全部隐藏。

脱敏标签页不得显示：

- 标题。
- URL。
- favicon。
- 搜索命中内容。
- 可从文本推断站点或页面的信息。

脱敏行只显示通用标签页图标、“内容已隐藏”、当前标签状态和操作按钮。窗口编号与标签页数量可以显示。

原始标题与 URL 不写入 DOM 文本节点、`title` 属性、`aria-label` 或可见调试属性。它们只存在于 React 内存状态中，用于搜索和 Chrome API 操作。

### 6.2 状态模型

使用以下两层状态：

- `globalMasked: boolean`：全局默认脱敏状态，初始为 `true`。
- `tabMaskOverrides: Map<TabId, boolean>`：单个标签页的显式脱敏状态覆盖。

单个标签页最终是否脱敏：

```text
如果 tabMaskOverrides 中存在 tabId，使用覆盖值；
否则使用 globalMasked。
```

### 6.3 全局切换

- 顶部眼睛按钮切换 `globalMasked`。
- 每次执行全局切换时清空 `tabMaskOverrides`，让所有标签页立即统一为新的全局状态。
- 按钮文字和无障碍标签明确表达即将执行的操作，例如“显示全部标签信息”或“隐藏全部标签信息”。

### 6.4 单项切换

- 每个标签页行提供独立眼睛按钮。
- 点击后将该标签页最终状态反转，并写入 `tabMaskOverrides`。
- 全局隐藏时，用户可只显示一个需要识别的标签页。
- 全局显示时，用户可单独隐藏敏感标签页。
- 标签页被关闭后，从覆盖表移除对应记录，避免无效状态积累。

### 6.5 搜索与隐私

- 搜索内部可以匹配真实标题和 URL，以保证功能完整。
- 匹配到脱敏标签页时，列表仍仅显示“内容已隐藏”。
- 结果数量可能间接表明存在匹配项，这是本地搜索功能的必要行为，首版接受该取舍。
- 不记录搜索历史，不发送分析事件。

## 7. 视觉设计

### 7.1 风格

- Chrome 原生工具型界面。
- 信息密度较高，但交互按钮保持至少约 36×36 CSS 像素的可点击区域；主要行高约 52–60 像素。
- 通过颜色、左侧强调条和文字共同标识当前标签页，不只依赖颜色。
- 不使用 Emoji 作为图标。

### 7.2 响应式布局

- 面向约 280–600 像素宽的 Side Panel。
- 窄宽度下筛选控件允许横向滚动或紧凑排列，不造成页面整体横向滚动。
- 标题和 URL 单行截断；用户可通过单独显示状态查看，但首版不添加展开详情面板。

### 7.3 主题

使用 `prefers-color-scheme` 自动适配浅色和深色主题。颜色通过语义 token 管理：

- 页面背景。
- 卡片/行背景。
- 主文本和次文本。
- 边框。
- 强调色。
- 危险操作色。
- hover、active、focus 状态。

## 8. 无障碍与键盘

- 使用语义化 `button`、`input` 和分组标题按钮。
- 所有纯图标按钮提供动态 `aria-label`。
- 焦点状态清晰可见。
- 标签页列表项的切换操作可以通过键盘触发。
- 分组头使用 `aria-expanded`。
- 状态提示使用 `aria-live="polite"`，不抢占焦点。
- 动效遵循 `prefers-reduced-motion`。

## 9. 状态与数据流

React 应用维护：

- `windowsWithTabs`
- `focusedWindowId`
- `query`
- `filter`
- `collapsedWindowIds`
- `globalMasked`
- `tabMaskOverrides`
- `loading`
- `error`

数据流：

```text
Chrome tabs/windows API
        ↓
查询与规范化层
        ↓
React 原始状态
        ↓
搜索 + 筛选 + 窗口排序
        ↓
脱敏展示模型
        ↓
Side Panel UI
```

Chrome 原始数据与脱敏后的展示数据应分层处理，避免组件在多个位置重复实现隐私逻辑。

## 10. 错误处理

- 初次查询失败：显示错误说明和“重试”按钮。
- 切换失败：提示“无法切换到该标签页”，并刷新列表。
- 关闭失败：提示“无法关闭该标签页”，保留当前项。
- 事件监听刷新失败：保留最后一次有效数据并显示非阻塞提示。
- Chrome API 不可用的普通浏览器开发环境：展示明确的“请在 Chrome 扩展环境运行”状态，便于 Vite 页面调试。

## 11. 测试策略

### 11.1 单元测试

- 搜索标题和 URL。
- 三类筛选逻辑。
- 当前窗口优先排序。
- 脱敏最终状态计算。
- 全局切换清空单项覆盖。
- 单项切换在全局隐藏/显示下均正确反转。
- 脱敏展示模型不包含标题、URL 和 favicon。

### 11.2 组件测试

- 加载、空状态和错误状态。
- 展开/折叠窗口。
- 点击行调用标签页激活和窗口聚焦。
- 关闭按钮不触发行点击。
- 单项脱敏按钮不触发行点击。
- 全局脱敏按钮统一更新全部行。
- Chrome 事件触发后列表刷新。

### 11.3 手动验收

- 在 Chrome 中加载构建后的未打包扩展。
- 多窗口、多标签页环境下验证分组和切换。
- 新建、更新、移动、激活和关闭标签页，确认实时同步。
- 验证全局隐藏、全局显示及单项覆盖组合。
- 验证脱敏 DOM 中不存在原始标题、URL 和 favicon。
- 验证浅色、深色、窄 Side Panel 和键盘操作。

## 12. 验收标准

1. 用户能在 Side Panel 中看到按窗口分组的全部可管理标签页。
2. 用户能按标题或 URL 搜索，并使用三种筛选模式。
3. 点击标签页可正确切换并聚焦其所属窗口。
4. 点击关闭按钮可关闭目标标签页且不会误切换。
5. 浏览器中标签页或窗口发生变化后，Side Panel 无需手动刷新即可同步。
6. 新 Side Panel 会话默认隐藏全部标题、URL 和 favicon。
7. 全局切换可一次显示或隐藏全部标签信息，并重置单项覆盖。
8. 每个标签页可独立反转其脱敏状态。
9. 脱敏状态下 DOM 和无障碍文本不暴露标题、URL 或 favicon。
10. 插件可通过项目测试和生产构建，并能作为未打包扩展在 Chrome 中加载。

## 13. 实施边界与后续扩展

当前架构应保留后续增加以下功能的空间，但首版不实现：

- Chrome Tab Groups 支持。
- 拖拽排序和跨窗口移动。
- 批量选择和批量关闭。
- 重复标签检测。
- 挂起不活跃标签页。
- 标签页会话保存和恢复。
